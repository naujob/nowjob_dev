# 2025-12-17 로그 파일 데이터 흐름 분석

## 1. FCM 토큰 등록 흐름 (앱 시작/페이지 로드 시)

### 실행 순서:
```
1. 📱 페이지 로드 완료 - FCM 토큰 등록 시도
   ↓
2. 🔥 [initTokenSystem] 토큰 시스템 초기화
   ↓
3. 🔥 [trySendToken] 토큰 미준비, 대기 중... (반복)
   ↓
4. 📱 앱 시작 시 FCM 토큰 등록 시도
   ↓
5. 📱 Android 앱 FCM 토큰 함수가 없음 (또는 iOS에서 토큰 수신)
   ↓
6. 🔥 [setToken] 토큰 수신: [토큰값]
   ↓
7. 🔥 [setToken] 토큰 준비 완료, 서버 전송 시도
   ↓
8. 🔥 [trySendToken] 모든 조건 충족! update_token 전송
   ↓
9. 🔥 [trySendToken] token: [토큰값]
   ↓
10. 🔥 [trySendToken] ✅ 전송 완료!
```

### 데이터 흐름:
- **클라이언트 (웹뷰)**: 페이지 로드 → 토큰 시스템 초기화 → 토큰 대기/수신
- **네이티브 앱**: FCM 토큰 생성 → JavaScript로 토큰 전달 (`setToken`)
- **클라이언트**: 토큰 수신 → 서버로 전송 (`/common_proc/update_token`)
- **서버 (PHP)**: 토큰 저장/업데이트

### 주요 함수 상세 설명:

#### 1. `initTokenSystem()` - 토큰 시스템 초기화
- **위치**: `application/shop/views/mobile/_layout/basic.php` (라인 196)
- **호출 시점**: 페이지 로드 시 자동 실행
- **기능**:
  - 페이지 로드 시 토큰 시스템 초기화
  - 기존 토큰이 있으면 복구 (`window.fcmToken`)
  - Socket.IO 연결 상태 확인
  - Socket 연결 대기 (최대 3초, 100ms 간격)
  - 조건 충족 시 `trySendTokenToServer()` 호출
- **처리 흐름**:
  ```
  페이지 로드
    ↓
  initTokenSystem() 실행
    ↓
  기존 토큰 확인 → 있으면 복구
    ↓
  Socket 연결 확인 → 연결되면 _socketReady = true
    ↓
  500ms 후 trySendTokenToServer() 시도
    ↓
  Socket 연결 대기 (최대 3초)
    ↓
  연결되면 trySendTokenToServer() 호출
  ```

#### 2. `setToken(token)` - 네이티브 앱에서 토큰 수신
- **위치**: `application/shop/views/mobile/_layout/basic.php` (라인 93)
- **호출 주체**: 네이티브 앱 (Android/iOS)
- **파라미터**: `token` - FCM 등록 토큰 문자열
- **기능**:
  - 네이티브 앱이 생성한 FCM 토큰을 받아 저장
  - 토큰 유효성 검사 (null, 빈 문자열, 'null' 문자열 체크)
  - 전역 변수에 토큰 저장 (`window.fcmToken`)
  - 토큰 준비 완료 플래그 설정 (`window._tokenReady = true`)
  - 조건 충족 시 `trySendTokenToServer()` 호출
- **처리 흐름**:
  ```
  네이티브 앱에서 FCM 토큰 생성
    ↓
  네이티브 앱이 JavaScript 호출: window.setToken("토큰값")
    ↓
  setToken() 실행
    ↓
  토큰 유효성 검사
    ↓
  window.fcmToken = token (저장)
  window._tokenReady = true (준비 완료)
    ↓
  trySendTokenToServer() 호출 시도
  ```
- **예시**:
  ```javascript
  // 네이티브 앱 (Android/iOS)에서 이렇게 호출:
  webView.evaluateJavaScript("window.setToken('ekPs6VhL6E-ouOF-qXpZ...')")
  
  // JavaScript에서 실행:
  window.setToken = function(token) {
    window.fcmToken = token;  // 토큰 저장
    window._tokenReady = true;  // 준비 완료
    trySendTokenToServer();  // 서버로 전송 시도
  }
  ```

#### 3. `trySendTokenToServer()` - 서버로 토큰 전송
- **위치**: `application/shop/views/mobile/_layout/basic.php` (라인 116)
- **호출 시점**: 
  - `setToken()`에서 토큰 수신 시
  - `initTokenSystem()`에서 초기화 후
  - Socket.IO 연결 완료 시
- **기능**:
  - 모든 조건이 충족되면 서버로 FCM 토큰 전송
  - 중복 전송 방지 (`window._updateSent` 플래그)
  - 조건 체크:
    1. 이미 전송했는지 (`_updateSent`)
    2. 토큰이 준비되었는지 (`_tokenReady`, `fcmToken`)
    3. Socket.IO가 연결되었는지 (`_socketReady`, `socket.connected`)
    4. 사용자 ID가 있는지 (`getUserId()`)
  - 조건 충족 시 Socket.IO로 `update_token` 이벤트 전송
  - 전송 성공 시 플래그 설정 및 로그 기록
- **처리 흐름**:
  ```
  trySendTokenToServer() 호출
    ↓
  조건 체크:
    ├─ 이미 전송했나? → YES: 종료
    ├─ 토큰 준비됐나? → NO: 대기
    ├─ Socket 연결됐나? → NO: 대기
    └─ 사용자 ID 있나? → NO: 대기
    ↓
  모든 조건 충족!
    ↓
  socket.emit("update_token", {
    user_id: user_id,
    token: window.fcmToken
  })
    ↓
  window._updateSent = true (중복 방지)
    ↓
  서버 로그 기록 (선택적)
  ```
- **전송 데이터**:
  ```javascript
  {
    user_id: "01012345678",  // 사용자 ID
    token: "ekPs6VhL6E-ouOF-qXpZ..."  // FCM 토큰
  }
  ```

#### ⚠️ 왜 Socket.IO로 Node.js 서버에 토큰을 전송하는가?

**핵심 이유: 성능 최적화를 위한 이중 저장 전략**

웹뷰에서 Socket.IO로 Node.js 서버에 토큰을 전송하는 이유는 **채팅 메시지 전송 시 빠른 토큰 조회**를 위해서입니다.

##### 1. 토큰 저장 경로 비교

| 전송 경로 | 대상 서버 | 저장 위치 | 용도 |
|----------|---------|----------|------|
| **Socket.IO** (`socket.emit("update_token")`) | Node.js 서버 | MongoDB (`chat.user` 컬렉션) | 채팅 메시지 푸시 발송 시 빠른 조회 |
| **HTTP API** (`/common_proc/update_token`) | PHP 서버 | MySQL (`st_member_device` 테이블) | 일반 푸시 알림 (채용제안, 지원 등) |

##### 2. 채팅 메시지 전송 시 토큰 조회 순서

채팅 메시지 전송 시 Node.js 서버는 다음 순서로 토큰을 조회합니다:

```javascript
// chatting/chat/chat_server.js (라인 677-685)
// 1순위: MongoDB에서 토큰 조회 (빠름 - 메모리 기반)
let token = target_user.token || "";

// 2순위: MongoDB에 없으면 MySQL에서 조회 (느림 - 디스크 I/O)
if (!token || token === "") {
    token = await new Promise((resolve) => {
        $exe.user.getUserTokenFromMySQL(target_user_id, resolve);
    });
}
```

##### 3. 성능 최적화 효과

- **MongoDB 조회 (1순위)**: 
  - 메모리 기반으로 매우 빠름
  - Socket.IO 연결 시 이미 메모리에 로드된 사용자 정보에서 즉시 조회 가능
  - MySQL 조회를 생략하여 디스크 I/O 감소

- **MySQL 조회 (2순위)**:
  - MongoDB에 토큰이 없을 때만 실행
  - 디스크 I/O가 발생하여 상대적으로 느림
  - 네이티브 앱에서만 토큰을 등록한 경우에 사용

##### 4. 전체 흐름

```
웹뷰 사용자
  ↓
Socket.IO로 토큰 전송 (socket.emit("update_token"))
  ↓
Node.js 서버 → MongoDB에 토큰 저장
  ↓
채팅 메시지 전송 시
  ↓
MongoDB에서 토큰 즉시 조회 (빠름) ✅
  ↓
없으면 MySQL에서 조회 (느림)
  ↓
FCM 푸시 알림 발송
```

##### 5. 네이티브 앱과의 차이점

- **네이티브 앱**: HTTP API로 PHP 서버(MySQL)에만 저장
  - 채팅을 사용하지 않는 경우에도 푸시 알림을 받을 수 있음
  - 채용제안, 지원 관련 푸시 알림에 사용

- **웹뷰**: Socket.IO로 Node.js 서버(MongoDB)에도 저장
  - 채팅 메시지 푸시 발송 시 빠른 조회를 위해 MongoDB에 저장
  - 채팅 기능을 사용하는 사용자에게 최적화

**결론**: 웹뷰에서 Socket.IO로 Node.js 서버에 토큰을 전송하는 것은 채팅 메시지 전송 시 MongoDB에서 빠르게 토큰을 조회하여 푸시 알림을 즉시 발송하기 위함입니다. 이는 성능 최적화를 위한 설계입니다.

#### 세 함수의 협력 관계:
```
1. 페이지 로드
   ↓
2. initTokenSystem() 실행
   → 기존 토큰 복구
   → Socket 연결 대기
   ↓
3. 네이티브 앱에서 토큰 생성
   ↓
4. setToken(token) 호출
   → 토큰 저장
   → _tokenReady = true
   ↓
5. trySendTokenToServer() 호출
   → 조건 체크
   → Socket 연결 대기 중이면 대기
   ↓
6. Socket.IO 연결 완료
   → _socketReady = true
   ↓
7. trySendTokenToServer() 재호출
   → 모든 조건 충족!
   → 서버로 토큰 전송 ✅
```

#### 요약:
| 함수 | 역할 | 호출 주체 | 주요 기능 |
|------|------|----------|----------|
| `initTokenSystem()` | 초기화 | 페이지 로드 시 자동 | 토큰 시스템 초기화, Socket 연결 대기 |
| `setToken(token)` | 토큰 수신 | 네이티브 앱 | 네이티브 앱에서 받은 토큰 저장 |
| `trySendTokenToServer()` | 토큰 전송 | 위 두 함수에서 호출 | 조건 충족 시 서버로 토큰 전송 |

**핵심 목적**: 네이티브 앱에서 생성한 FCM 토큰을 서버로 안정적으로 전송하여 푸시 알림을 받을 수 있도록 하는 것

## 3. 채팅 메시지 전송/수신 흐름

### 실행 순서 (메시지 전송):
```
1. 사용자가 채팅 메시지 입력 및 전송 버튼 클릭
   📍 페이지: application/shop/views/mobile/chat/chat_view.php
   📍 함수: send_message() (라인 1979 또는 2830)
   📍 이벤트: $("#btnSend").click() → send_message() 호출
   ↓
2. 메시지 객체 생성 및 Socket.IO로 전송
   📍 함수: send_message() 내부
   📍 코드: socket.emit("message_insert", message, rm_info.rm_users)
   📍 전송 데이터: {rm_idx, user_id, chat_type, mg_type, mg_text, mg_dt, mg_reads}
   ↓
3. Node.js 서버에서 메시지 수신 및 처리
   📍 파일: chatting/chat/chat_server.js
   📍 이벤트 핸들러: socket.on('message_insert', async function(data, rm_users)) (라인 450)
   📍 처리:
      - MongoDB 연결 확인
      - 나간 채팅방 여부 확인 (exit_yn='Y' 체크)
      - 메시지 DB 저장
   ↓
4. MongoDB에 메시지 저장
   📍 함수: $exe.chat.insertMessage(data, callback)
   📍 파일: chatting/chat/controller/chat_controller.js
   📍 저장 위치: MongoDB `room` 컬렉션의 `rm_messages` 배열
   📍 저장 내용: 메시지 정보 + 사용자 정보 + 읽음 상태 리스트
   ↓
5. Socket.IO를 통해 실시간 브로드캐스트
   📍 코드: io.sockets.in(target_rm_idx).emit('message_insert_return', ret) (라인 498)
   📍 이벤트: 'message_insert_return'
   📍 대상: 해당 채팅방(rm_idx)에 접속한 모든 클라이언트
   ↓
6. FCM 토큰 조회 및 푸시 알림 발송
   📍 파일: chatting/chat/chat_server.js (라인 672-710)
   📍 토큰 조회 순서:
      1순위: MongoDB에서 조회 (target_user.token) - 빠름 ✅
      2순위: MongoDB에 없으면 MySQL에서 조회 (getUserTokenFromMySQL) - 느림
   📍 발송 조건: 채팅방에 있지 않은 사용자 (last_location !== "chat_room")
   📍 함수: send_fcm(idx, push) (라인 50)
   📍 푸시 내용: 발신자 이름, 메시지 내용, 채팅방 URL
   📍 중요: 웹뷰에서 Socket.IO로 전송한 토큰은 MongoDB에 저장되어 1순위로 빠르게 조회됨
```

### 실행 순서 (메시지 수신):
```

   ↓
2. 메시지 데이터 파싱 및 처리
   📍 함수: message_insert_return() 또는 socket.on("message_insert_return") 내부
   📍 데이터: ret.data (메시지 배열)
   📍 로그: "🔥 [실시간] 수신된 메시지: {메시지 데이터}"
   ↓
3. 내 메시지 여부 확인

   ↓
4. 임시 메시지 교체 (있는 경우)
   📍 로직: 임시 메시지(data-temp-message)가 있으면 서버 응답으로 교체
   📍 로그: "🔥 [실시간] 임시 메시지 교체"
   ↓
5. UI에 메시지 표시

      - 읽음 카운트 표시 (내 메시지인 경우)
      - 채팅방 UI에 추가 (prepend 또는 append)
   📍 함수: scrollBottom() - 채팅창 스크롤을 맨 아래로 이동
```

### 데이터 흐름 (상세):

#### 클라이언트 사이드 (전송):
- **페이지**: `application/shop/views/mobile/chat/chat_view.php`
- **입력**: 사용자가 `#chatTxt` 입력란에 메시지 입력
- **전송 버튼**: `#btnSend` 클릭 이벤트 (라인 1971)
- **전송 함수**: `send_message()` (라인 1979)
  - 메시지 유효성 검사 (빈 메시지 체크)
  - 사용자 ID 확인 (`g_user_id`)
  - 메시지 객체 생성:
    ```javascript
    {

## 4. FCM 푸시 알림 발송 흐름 (채팅 메시지)

### 실행 순서 (Node.js 서버):
```

   📍 함수: send_fcm(idx, data) (라인 50)

   ↓

   📍 코드: const registrationToken = data["no_token"] (라인 114)
   📍 검증: 토큰이 없거나 비어있으면 함수 종료 (라인 52-54)
   ↓
3. 메시지 텍스트 처리
   📍 코드: message_text = data["no_text"] (라인 117)
   📍 처리: "[알 수 없음]" → "사용자"로 교체 (라인 118-123)
   📍 목적: 발신자 이름이 없는 경우 기본값 설정

   📍 코드: const chat_url = data["no_url"] || "" (라인 74)

   📍 예시: "/chat/chat_view?rm_idx=874"
   ↓

   📍 코드: const message = {...} (라인 77-173)
   📍 구성 요소:
      - notification: {title: 제목, body: 메시지 내용}

          }
        }
      - token: FCM 등록 토큰
   📍 중요: Firebase Admin SDK는 data 필드의 모든 값이 문자열이어야 함 (String() 변환 필수)
   ↓
6. Firebase Admin SDK로 메시지 전송
   📍 코드: fcm_admin.messaging().send(message) (라인 185)
   📍 라이브러리: Firebase Admin SDK
