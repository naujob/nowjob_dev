# 프로젝트 작업 표준 프로세스 (Work Process)

이 스킬은 사용자의 요청을 받았을 때 다음의 4단계 순서를 엄격히 준수하여 작업을 진행합니다.

## [1단계] 코드 리서치 (Code Research)
- **목표:** 강력한 인풋으로 좋은 아웃풋 만들기.
- **행동:** 관련 소스 코드를 깊이 읽고 동작 원리와 세부 사항을 완벽히 파악합니다.
- **결과물:** 분석이 끝나면 `research.md` 파일에 상세 분석 보고서를 작성합니다.

## [2단계] 계획하기 (Planning)
- **목표:** 실제 코드베이스를 바탕으로 한 구체적인 설계.
- **행동:** `plan.md` 파일을 생성하여 다음 내용을 포함합니다.
  - 작은 단계들로 나누어서 계획하기
  - 구현할 기능의 상세 설명 (예: ETF 리밸런싱 등)
  - 접근 방식 상세 설명
  - 수정 및 생성될 파일 경로
  - **트레이드오프 (선택에 따른 장단점)**
- **결과물:** `plan.md` 마크다운 파일.

## [3단계] 사용자 리뷰 및 피드백 (Review)
- **목표:** 사용자의 의도와 일치하는지 확인.
- **행동:** 작성된 `plan.md`를 사용자에게 보여주고 리뷰를 요청합니다. 
- **업데이트:** 사용자가 주석이나 메시지로 피드백을 주면 계획을 즉시 수정하여 업데이트합니다.

## [4단계] 구현 시작 (Implementation)
- **목표:** 최종 승인된 계획에 따른 코드 작성.
- **행동:** 모든 리뷰가 완료된 후 실제 코딩을 시작합니다.

## [5단계] 코드 정밀 검사 (Validation & QA)
- **목표:** 완벽하고 안전한 코드 완성.
- **체크리스트:**
  1. **문법 검사:** 오타나 괄호 누락, 세미콜론(`;`) 누락 등 문법 오류가 없는지 확인.
  2. **오류 예측:** 변수가 비어있거나(Null), 파일이 없는 경우 등 발생 가능한 에러 상황을 미리 방지했는지 검토.
  3. **주석 확인:** 약속한 대로 초등학생도 이해할 수 있는 쉬운 한글 주석이 달려있는지 확인.
- **결과물:** 검사가 완료되면 "검사 완료: 이상 없음" 또는 "수정 사항 발생" 보고 후 최종 코드 제출.
